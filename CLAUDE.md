# Working on retinaoct

## ⚠️ BEFORE YOU TOUCH ANY SQL — READ THIS

**The daily D1 read allowance has been exhausted FIVE separate times. Every
one took the site down. Every one was found by a user, not by a check. Every
one had the same cause.**

| commit | what happened |
|---|---|
| `976571d` | facets recomputed on every request |
| `2abef40` | `idx_img_sort_default` missing — every page load sorted 153,045 rows |
| `06d6f5e` | three leaks at once: an unindexed `ORDER BY`, no edge cache, four scans per search |
| `f16d480` | a filtered search still running three full scans |
| `583f18d` | `LIKE '%term%'` plus negated biomarkers — **9,128,605 reads in one day** |

### The one mistake behind all five

**Judging a query by how many rows it RETURNS instead of how many it READS.**

D1 bills rows *scanned*. `LIMIT 24` takes nothing off the bill. A `WHERE`
clause takes nothing off the bill unless an index can actually use it.
**Twenty-four rows on screen can be 153,045 rows charged.** The allowance is
5,000,000 a day, so thirty such queries end the day.

### Patterns that always scan — none of them look expensive

```sql
WHERE col = 1                  -- no index on col
WHERE a = ? ORDER BY b, c      -- index covers a but NOT the sort, so every
                               -- match is read and sorted before the LIMIT
WHERE col LIKE '%x%'           -- leading wildcard, never indexable
WHERE COALESCE(col,0) = 0      -- negation: a partial index covers the rows
WHERE col NOT IN (...)         -- that ARE set, i.e. the complement
COUNT / SUM / GROUP BY         -- over a filtered subset: always reads it all
```

Plus the one that is not SQL at all: **an endpoint with no edge cache pays
again on every single view.** `/api/image` once cost 2,156 rows per view
across 153,045 pages because `cf-cache-status` was `DYNAMIC`.

### What to do instead, in order of preference

1. **Don't query D1.** The corpus is static. `public/data/corpus.json` holds
   the whole searchable index in 580 KB and the browser filters it in memory
   at zero cost. Anything a user can trigger repeatedly belongs there.
   Rebuild it with `scripts/build_static_index.py`.
2. **Precompute.** `facets_global` is one row holding every unfiltered count.
3. **Index it** — and make the index cover the `ORDER BY`, not just the
   `WHERE`. Note the write budget: 100,000 rows/day, and an index on `images`
   is 153,045 entries, so a full index cannot be built in one day. Build it in
   `scripts/build_olives_index.py` during a rebuild instead, where it is part
   of the bulk load.
4. **Edge-cache the response**, and never cache something that must be fresh
   (verification reads bypass the cache deliberately).

### How to check, before shipping

```bash
# plans and table sizes, locally — needs no quota
npx wrangler d1 export retinaoct-olives --remote --output full.sql   # NOT metered
sqlite3 live.db < full.sql
python3 scripts/check_query_cost.py live.db

# then the only authoritative number: D1's own accounting, on a preview deploy
curl -s 'https://retinaoct.com/api/search?<filters>&debug=1' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["_rows_read"])'
```

**EXPLAIN is not a verdict.** It calls the default sort a `SCAN` though the
index stops it at 24 rows, and calls a negated biomarker a covering-index scan
though it reads all 153,045. Only `rows_read` from D1 settles it.

**Budget:** anything a user can trigger repeatedly should stay under ~1,000
rows read. Over ~10,000, justify it in the commit message and make sure the
caller is cached.

### If the allowance is already gone

It resets at 00:00 UTC and nothing restores it sooner. But `wrangler d1
export` is a backup operation and is **not metered as row reads**, so the data
can still be pulled and served statically — that is how the site stayed up
during a clinician meeting on 2026-11-23.

## Other things worth knowing

- **Secrets** live in Doppler (`doppler run -p retinaoct -c dev -- …`). Never
  put a secret value in a session transcript; the repo is public.
- **CSS is cache-busted by content hash.** After editing `public/styles.css`,
  run `python3 scripts/stamp_assets.py` or the change will not reach anyone.
- **Assert that an edit landed.** Two bugs shipped from a silent no-op
  `replace()` whose search string did not match. Check, don't assume.
- **Schema lives in the repo**, not only in D1: `scripts/sql/schema.sql`,
  regenerated by `scripts/sql/capture_schema.py`. An index was lost once
  because it existed nowhere else.
- **Verification mode** is gated on a D1 row; see the project memory for the
  on/off commands.
